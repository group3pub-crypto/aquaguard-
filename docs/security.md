# Security

## Roles
resident (read) < maintenance (+ack/snooze/resolve) < admin (+valve, override, role, retrain, forecast-generate). Enforced server-side in the backend; the dashboard and bot only mirror it.

## Secrets (fail closed)
- No secrets in the repo. `.env` is generated by `make env` with `openssl rand`; `.env.example` contains `CHANGE_ME` placeholders, and `make check-env` rejects any left in `.env`. Which component rejects which placeholder is listed at the top of `.env.example`; do not assume more than that.
- Backend in `production` refuses to start without a strong `SECRET_KEY` (>= 32 chars).
- Compose uses `${VAR:?...}` for the required secrets; the mosquitto entrypoint rejects placeholder `MQTT_PASSWORD`s. Secrets are environment variables from a `0600` `.env` (the services do not read `*_FILE`); use your orchestrator's secret store to inject them in managed environments.

## Network and containers
- Production: Caddy terminates TLS (HSTS, security headers, body limit, JSON access log); only 80/443 and MQTT 8883 are published. Backend trusts `X-Forwarded-*` only from the proxy's fixed address (`FORWARDED_ALLOW_IPS`).
- Database: the backend runs as `aquaguard_app` (DML only); migrations run as `aquaguard_owner` in a one-shot service; backups use a read-only role. The database network is `internal`.
- All services: `cap_drop: ALL`, `no-new-privileges`, read-only root filesystems with tmpfs, memory/CPU limits, non-root application images.
- Shipped ML models are pickles trained at build time and verified against a SHA-256 manifest (`MODEL_MANIFEST_REQUIRED=true`); the models volume is mounted read-only.

## Application
- JWT bearer auth with expiry (`ACCESS_TOKEN_EXPIRE_MINUTES`); no revocation yet.
- CORS limited to `ALLOWED_ORIGINS`.
- Rate limiting and WebSocket authentication are implemented in the backend (see its code/tests for specifics).
- Bot service account: create it by registering a user and promoting it with `PUT /api/v1/auth/users/{id}/role` (admin or maintenance); `make seed` does not create it. Set `BOT_API_USERNAME`/`BOT_API_PASSWORD`.
- Bot: admin ids from env, link approval by admin, role re-check on every callback, valve changes require a confirmation press, tokens never logged, MarkdownV2 escaping.

## CI
gitleaks secret scanning, pip-audit and npm audit (reporting only), pre-commit `detect-private-key`.

Report vulnerabilities per `SECURITY.md`.
